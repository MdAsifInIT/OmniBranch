# Observability and Metrics

OmniBranch provides local-first observability and health telemetry for campaign execution, token expenditure, semantic caching performance, and event store integrity.

## Token Usage Tracking

All AI engine invocation adapters track token usage metrics and record normalized usage events into the canonical JSONL event log.

- **Prompt Tokens**: Input tokens processed per worker invocation.
- **Completion Tokens**: Output tokens generated by AI engines.
- **Cached Tokens**: Prompt tokens reused via provider prompt caching or semantic cache hits.
- **Provider & Model Metadata**: Attribution per provider (Codex, Claude, OpenCode, Antigravity) and specific model release.

## Cost Dashboard CLI Commands

Operators can inspect token expenditure and cost estimates using built-in CLI commands:

- `omnibranch report --cost`: Renders detailed token consumption breakdowns by lane, provider, and model, alongside estimated cost calculations.
- `omnibranch status --metrics`: Displays real-time token burn rate, active concurrency limits, and progress toward configured budget ceilings.

Example summary output:

```text
OmniBranch Cost Summary
-----------------------
Campaign ID: camp_89f2a
Total Input Tokens:   142,500
Total Output Tokens:   18,200
Cached Tokens:         54,000
Estimated Total Cost:  $0.42 USD

Lane Breakdown:
  - refactor-lane: 85,000 in / 11,000 out ($0.26)
  - test-lane:     57,500 in /  7,200 out ($0.16)
```

## Semantic Cache Hit Rates

The semantic caching layer tracks request evaluation statistics to evaluate performance and efficiency:

- **Cache Hits**: Identical or semantically matching requests resolved instantly from local cache.
- **Cache Misses**: Deterministic queries executed against external AI engine APIs.
- **Cache Bypasses**: Non-deterministic intents (e.g., dynamic timestamps, environment reads) explicitly routed around the cache.
- **Hit Rate**: Calculated as `Hits / (Hits + Misses) * 100%`.

Inspect cache performance via:

```bash
omnibranch status --cache
```

## Event Store Health Metrics

The event store and projection subsystem monitor store health and synchronization metrics:

- **Sequence Continuity**: Verification that global and per-stream event sequence numbers have no missing gaps.
- **Projection Sync Latency**: Time offset between canonical JSONL event emission and SQLite projection materialization.
- **Schema Migration Version**: Active event envelope and SQLite projection schema version.
- **Reindex Counter**: Frequency and timing of projection rebuilds from JSONL logs.

Verify system health and diagnose issues using:

```bash
omnibranch doctor --health
```
